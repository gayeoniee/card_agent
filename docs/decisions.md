# 결정 기록 (card_agent)

되돌리기 번거로운 결정만 적는다. 번호는 `CA-0xx` — dev 의 `D-0xx` 와 부딪히지 않게
접두사를 갈라 둔다.

---

## CA-001 · Python 3.12 고정, 의존성은 uv 로만

`requires-python = ">=3.12,<3.13"` 과 `.python-version` 을 같이 둔다. `pip` 을 쓰지
않고 `uv add`/`uv remove` 로만 고치며 `uv.lock` 을 커밋한다.

dev 의 D-001 과 같은 이유다. 여기서 판을 달리 깔면 폴더째 dev 로 옮기는 순간
락파일이 두 벌이 된다.

## CA-002 · dev 레포를 부르지 않는다 — 계약은 `scene.json` 하나

`card_agent` 는 dev 의 config·DB·모델을 하나도 import 하지 않는다. 바깥과는
`scene.json` 한 장으로만 말하고, 그 출처는 `src/contract.py` 하나다.

개인 레포에서 굴리다가 폴더째 dev 에 넣을 수 있어야 한다는 것이 이 설계의 목적이다.
dev 를 한 줄이라도 부르는 순간 그 성질이 사라진다. 사본 추적은 명시 대신
`pyproject.toml` 의 `version` 으로 한다.

이 결정의 대가: 산책 데이터 같은 dev 쪽 값을 장면에 못 쓴다. `scene.weather` ·
`scene.time_of_day` 자리만 optional 로 비워 두고, 채우는 일은 나중 카드로 넘긴다.

## CA-003 · 계약 필드 이름은 앱을 따라간다

`statLabel` · `fit` · `motes` 처럼 앱의 `ImmersiveScene` · `DexCard` 에 이미 있는
이름을 그대로 쓴다. 파이썬 쪽 이름(`stat_label`)은 alias 로만 오간다.

새 어휘를 만들면 앱에 붙일 때 이름 대조표가 하나 더 생긴다. 그 표는 아무도
갱신하지 않는다. 모르는 필드는 `extra="forbid"` 로 거절해서, 이름이 어긋난 JSON 이
조용히 통과하지 못하게 한다.

## CA-004 · 생일 월 → 작물은 룰 테이블이다 (모델 아님)

카드가 정확히 12장이고 달도 12개라 1:1 로 떨어진다. `templates/crops.toml` 표
하나로 끝내고 모델을 쓰지 않는다.

표의 `no` · `statLabel` · `stat` · `foil` 중 **확인된 값은 배추 = No.01 하나뿐**이다.
나머지 11장은 앱의 실제 `DexCard` 목록을 손에 넣기 전의 자리값이고, 목록이 오면
TOML 만 고치면 된다 — 파이프라인은 건드릴 것이 없다.

## CA-005 · 누끼(rembg)는 선택 의존성으로 가른다

rembg 는 onnxruntime 과 모델 가중치를 끌고 오고 첫 실행에 네트워크를 탄다. 기본
설치에 넣지 않고 `uv sync --extra cutout` 으로 가른다. `skin-screening` 의
`--extra model` 과 같은 방식이다.

없을 때는 500 이 아니라 **곱게 실패한다**(`CutoutUnavailable`, 503 성격). 알파가
이미 있는 PNG 를 넣으면 rembg 를 부르지 않고 그대로 쓰므로, 누끼 설비 없이도 나머지
파이프라인 전체가 돈다. 이 길이 없으면 테스트가 매번 가중치를 받아야 한다.

## CA-006 · accent2 는 두 번째 군집이 아니라 accent 의 밝은 짝

털색 군집 두 개를 그대로 쓰면 강아지에 따라 보색이 튀어나와 장면이 요란해진다.
앱의 배추 장면도 `#EEBE93` · `#F5D9BE` 로 같은 색의 밝은 짝이다. 그래서 accent 를
밝은 쪽으로 섞어 accent2 를 만든다.

검은 개·흰 개의 털색을 그대로 쓰면 이머시브에서 빛이 안 보이거나 다 타 버리므로,
색상(hue)은 두고 명도·채도만 쓸 수 있는 범위로 끌어당긴다. 강아지의 색이 아닌 값이
되는 것이 대가지만, 안 보이는 것보다 낫다.

## CA-007 · 씨(seed)는 Kotlin `String.hashCode` 규약을 따른다

앱의 `seedOf(text)` 가 먼지·이슬 배치를 고정한다. 같은 값을 내야 앱에서 기대한
자리에 먼지가 앉으므로, Kotlin/Java 의 `String.hashCode`(31 진법 · UTF-16 코드 단위 ·
32비트 부호 있는 정수)를 그대로 구현했다. `"abc"` = 96354, `"Aa"` = `"BB"` = 2112,
`"polygenelubricants"` = -2147483648 로 대조했다.

**앱 구현을 직접 보고 맞춘 것이 아니다.** 다르면 고칠 곳은 `seed_of` 한 함수뿐이다.

씨의 재료는 강아지 id 인데 강아지 테이블이 아직 없어서(스키마에 존재하지 않는다)
지금은 `"이름:생일"` 을 쓴다. DB 가 생기면 `build_scene(dog_key=...)` 로 넣는다 —
그때 씨가 바뀌므로 이미 만든 장면의 배치가 한 번 바뀐다.

## CA-008 · 음악은 provider 인터페이스 + mock 으로 계약을 먼저 잡는다

음악 생성 서비스가 아직 정해지지 않았다. `generate(prompt, seconds) -> bytes`
하나짜리 인터페이스와 mock 만 두고, 실제 서비스 연동은 별도 카드로 미룬다 (그 카드의
첫 항목은 **상업 이용 라이선스 확인**이다). `skin-screening` 이 `serve.py --mock` 으로
계약을 먼저 잡은 것과 같은 방식이다.

루프 이음새와 OGG 변환은 provider 가 아니라 `src/loop.py` 가 맡는다. 서비스가 바뀌어도
루프 규격은 그대로여야 하기 때문이다.

## CA-009 · 음악 실패는 파이프라인에서 유일하게 삼키는 예외

①~⑥ 은 오프라인·0원·즉시고 ⑦만 네트워크·유료·느리다. 음악이 실패하면 `bgm` 을
null 로 두고 카드는 그대로 낸다 — 앱의 `SceneMusic` 이 asset 이 없으면 조용히 아무것도
안 하도록 이미 짜여 있다("소리가 안 나도 화면은 산다").

그림 단계(누끼·원화·합성)의 실패는 삼키지 않고 그대로 올린다. 카드 없이 나갈 이유가
없다.

## CA-010 · OGG · 블록 단위 쓰기는 `convert_audio.py` 규격 그대로

MP3 는 인코더가 앞뒤에 빈 프레임을 붙여서 이어 붙이면 29초쯤마다 "툭" 소리가 난다.
그래서 OGG/Vorbis 로 쓴다. libsndfile 에 통째로 넘기면 윈도우에서 스택 오버플로로
조용히 죽으므로 `BLOCK = 1<<16` 씩 잘라 넘긴다. 둘 다 앱 레포의 `convert_audio.py` 가
이미 겪고 적어 둔 것이라 그대로 따랐다.

이음새는 꼬리를 머리에 **등파워로** 겹쳐 만든다. 직선으로 섞으면 겹친 구간이 0.7배로
한 번 꺼진다. 겹치는 구간의 시작이 원래 그 앞에 있던 소리라, 마지막 샘플에서 첫
샘플로 넘어갈 때 값이 튀지 않는다 — 재보니 이음새의 튐이 안쪽 계단보다 작았다.
사람 귀로는 30초를 두 바퀴 이상 들어야 확인된다.
